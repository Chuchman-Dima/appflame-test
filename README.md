# appflame-test

## Опис проєкту

Проєкт об’єднує кілька аналітичних завдань:

- аналіз платіжних даних
- вивчення причин відмов у платіжних транзакціях

Основна робота зберігається в папці `tasks/`.

## Документація по папках і файлам


## `tasks/`

Це основна робоча папка проєкту. Тут лежать всі аналітичні задачі, дані, SQL і результати.

### `tasks/Task-1.ipynb`

Notebook для аналізу платіжних даних.

#### Що робить

- читає CSV з платіжними транзакціями
- перевіряє структуру даних
- конвертує `event_time` в datetime
- додає часові фічі: місяць, день, година, хвилина, день тижня
- оцінює якість даних: дублікти, пропуски, типи полів
- аналізує розподіл транзакцій за статусом
- оцінює success rate
- аналізує кількість транзакцій на користувача
- перевіряє розподіл ціни/суми платежу
- вивчає активність по місяцях, днях місяця та днях тижня
- аналізує `error_type` для невдалих платежів

#### Очікуваний вхідний файл

```text
../data/test_1_payment_data/test_1_payment_data.csv
```

#### Основні показники, знайдені в notebook

- 566413 транзакцій
- 115245 унікальних користувачів
- 0 дублікатів
- success rate ≈ 44.57%
- fail ≈ 313954
- success ≈ 252459

### `tasks/Task-3.ipynb`

Notebook для A/A і A/B тестування.

#### Що робить

- завантажує дані експерименту
- розділяє користувачів на контрольну та тестову групи
- аналізує поведінку в обох групах
- застосовує Mann-Whitney U test
- порівнює результати до і під час експерименту

#### Основна ідея

Тестова і контрольна групи формуються за допомогою `sender_id` або аналогічного критерію поділу, а потім порівнюються за ключовим KPI.

#### Результати з notebook

- A/A p-value ≈ 0.6690
- A/B p-value ≈ 0.5045

Висновок: статистично значущої різниці між групами не виявлено.

### `tasks/Task-4.ipynb`

Notebook для розрахунку LTV (Lifetime Value).

#### Що робить

- обробляє дані про користувачів і транзакції
- приводить дати до правильного формату
- перевіряє пропуски та некоректні значення
- розраховує LTV на одного користувача
- оцінює LTV6 (LTV за 6 місяців)
- аналізує платників і частку платників
- показує LTV за когортами

#### Основні поля даних

- `rd` — дата реєстрації
- `customer_id` — ID користувача
- `TD` — дата транзакції
- `revenue_usd` — дохід у доларах

#### Результати з notebook

- 3576 унікальних користувачів
- 3517 користувачів взято в розрахунок
- 204 платники
- LTV6 на одного зареєстрованого користувача ≈ $0.802
- LTV6 на одного платника ≈ $13.83

### `tasks/SQL/`

Папка, що містить SQL-частину проєкту.

#### `tasks/SQL/SQL.sql`

Основний SQL-скрипт. Містить 4 завдання:

1. Рейтинг працівників за зарплатою
2. Рейтинг працівників по департаментах
3. Визначення різниці зарплати від попереднього працівника через `LAG()`
4. Частка зарплати працівника в загальному фонді департаменту

Схема таблиці:

```sql
employees (
    id,
    name,
    department,
    salary
)
```

Завдання виконані з використанням віконних функцій:

- `ROW_NUMBER()`
- `LAG()`
- `SUM() OVER(...)`

#### `tasks/SQL/Тестове SQL.docx`

Word-документ з SQL-тестовим завданням або його описом.
